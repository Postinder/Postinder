Postinder Deploy

Guia de Deploy do Postinder

Documento com os passos e configurações usados para publicar o frontend, backend e banco de dados da branch newStructure.

Atualizado em 01/06/2026.

Arquitetura Publicada

Parte Plataforma Função
Frontend Vercel Hospeda o app React/Vite em https://postinder.vercel.app.
Backend Render Web Service Hospeda a API Express/Node da pasta backend.
Banco de dados Supabase Postgres Armazena tabelas, usuários, clientes, posts, arquivos e feedbacks.
Repositório GitHub Organização Postinder, repositório Postinder/Postinder, branch newStructure.

Preparação no GitHub

  1. O repositório foi movido para a organização Postinder.
  2. A branch de produção usada foi newStructure.
  3. A Vercel foi instalada/configurada na organização para acessar o repositório.
  4. Foi feito push das correções necessárias para deploy.
git add -A
git commit -m "Configure backend CORS for production"
git push origin newStructure

Depois, foi criado outro commit para corrigir o start do backend em produção:

git add backend/package.json
git commit -m "Fix backend production module format"
git push origin newStructure

Correções Feitas no Código

CORS no backend

Foi adicionada a dependência cors para permitir que o frontend da Vercel chame o backend hospedado em outro domínio.

npm install cors
npm install -D @types/cors

No arquivo backend/src/app.ts, foi configurado CORS com a variável APP_PUBLIC_URL e suporte local para http://localhost:5173.

Correção de módulo no backend

O Render estava falhando com exports is not defined in ES module scope. A causa era o package.json do backend declarar "type": "module", enquanto o TypeScript compilava para CommonJS.

A correção foi remover "type": "module" de backend/package.json.

Build validado localmente

cd backend
npm run build
node dist/server.js

O endpoint /health respondeu com status OK após a correção.

Banco no Supabase

  1. Foi criado um projeto Supabase chamado Postinder.
  2. No SQL Editor, foi colado o conteúdo completo de database/001_initial_schema.sql.
  3. O script criou as tabelas users, clients, posts, files e feedback.
  4. O script também criou índices e inseriu o admin e cliente de teste.

Importante: no SQL Editor deve ser colado o conteúdo do arquivo SQL, não o caminho database/001_initial_schema.sql.

Credenciais de teste criadas pelo SQL

Admin:
E-mail: admin@postinder.local
Senha:  Admin@123456

Cliente:
E-mail: cliente@example.com
Senha:  Cliente@123456

Connection string usada no backend

Foi escolhida a opção Session pooler no Supabase, porque a conexão direta pode depender de IPv6.

DATABASE_URL=postgresql://postgres.PROJECT_REF:SENHA_URL_ENCODED@aws-1-us-west-2.pooler.supabase.com:5432/postgres?sslmode=require

Exemplo de encoding: se a senha contém @, ela deve virar %40 na URL.

Supabase Storage

  1. No Supabase, abrir Storage.
  2. Criar um bucket chamado postinder-uploads.
  3. Marcar o bucket como público para que o frontend consiga carregar as imagens e arquivos.
  4. Em Project Settings > API, copiar o Project URL e a chave service_role.
  5. Adicionar esses valores no Render como SUPABASE_URL e SUPABASE_SERVICE_ROLE_KEY.

Frontend na Vercel

  1. Foi criado um novo projeto na Vercel a partir do GitHub.
  2. Repositório selecionado: Postinder/Postinder.
  3. Branch usada: newStructure.
  4. Preset selecionado: Vite.
  5. Root directory configurado como apps/admin.

Configurações de build

Framework Preset: Vite
Root Directory: apps/admin
Install Command: npm install
Build Command: npm run build
Output Directory: dist

Variáveis de ambiente na Vercel

VITE_API_URL=https://SUA-URL-DO-RENDER.onrender.com/api/v1
VITE_APP_URL=https://postinder.vercel.app
VITE_APPROVAL_BASE_URL=https://postinder.vercel.app

Depois de adicionar ou alterar variáveis na Vercel, é necessário fazer redeploy em Deployments > Redeploy.

Backend no Render

  1. No Render, foi escolhido New Web Service.
  2. O repositório selecionado foi Postinder/Postinder.
  3. A branch selecionada foi newStructure.
  4. O serviço foi configurado como Node.
  5. O Root Directory foi configurado como backend.

Configurações do Web Service

Name: postinder-api
Language: Node
Branch: newStructure
Region: Oregon (US West)
Root Directory: backend
Instance Type: Free

Comandos no Render

Build Command: npm install --include=dev && npm run build
Start Command: npm run start

O --include=dev garante que o TypeScript seja instalado mesmo com NODE_ENV=production.

Variáveis de ambiente no Render

NODE_ENV=production
PORT=10000
DATABASE_URL=postgresql://postgres.PROJECT_REF:SENHA_URL_ENCODED@aws-1-us-west-2.pooler.supabase.com:5432/postgres?sslmode=require
JWT_SECRET=troque-por-uma-chave-grande-e-secreta
JWT_EXPIRY_MINUTES=15
JWT_REFRESH_EXPIRY_DAYS=7
LOG_LEVEL=info
SUPABASE_URL=https://PROJECT_REF.supabase.co
SUPABASE_SERVICE_ROLE_KEY=cole-a-chave-service-role-do-supabase
APP_PUBLIC_URL=https://postinder.vercel.app

Não commitar segredos: a DATABASE_URL real e o JWT_SECRET devem ficar só no painel do Render, não em arquivos do Git.

Problemas Encontrados e Soluções

Problema Causa Solução
Login local falhando A senha correta do admin era Admin@123456, não admin. Usar as credenciais do seed SQL.
Backend local não conectava ao Postgres localhost resolvia para IPv6 no Windows. Trocar a URL local para 127.0.0.1:5433.
Supabase SQL Editor deu erro em database Foi colado o caminho do arquivo em vez do conteúdo SQL. Copiar e colar todo o conteúdo de database/001_initial_schema.sql.
Render falhou no build NODE_ENV=production podia impedir instalação de dev dependencies. Usar npm install --include=dev && npm run build.
Render falhou no start com exports is not defined "type": "module" conflitava com output CommonJS do TypeScript. Remover "type": "module" de backend/package.json.
Frontend e backend em domínios diferentes O navegador bloqueia chamadas sem CORS. Adicionar cors no backend e liberar APP_PUBLIC_URL.

Observação Sobre Uploads

Em desenvolvimento local, o backend salva arquivos na pasta uploads.

Em produção, os uploads foram configurados para ir ao Supabase Storage no bucket postinder-uploads. Isso evita perda de arquivos em restart/redeploy do Render.
